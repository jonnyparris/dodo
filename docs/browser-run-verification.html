Dodo UI in Browser Run

A secure feedback loop: Dodo sessions drive a real Cloudflare Browser Run browser to load and verify the Dodo UI — without making the UI public.

Status: VERIFIED END-TO-END

A Browser Run browser (running in Cloudflare's cloud, not on the user's network) authenticated to the Dodo UI via a Cloudflare Access service token, loaded the app, and hit the API — all three API probes returned 200. Anonymous browsers are redirected to the Access login page.

Architecture

How it works

  1. A Dodo session calls the browser-run-worker gateway over HTTP MCP (JSON-RPC), authenticated with a Bearer AUTH_TOKEN stored on the user's machine.
  2. The gateway launches a real Chromium browser via Cloudflare's Browser Run CDP endpoint and runs a step list: setViewport, setHeaders, navigate, evaluate, screenshot, click, type, …
  3. The setHeaders step injects CF-Access-Client-Id / CF-Access-Client-Secret — a dedicated service token ("Dodo Browser Sessions") minted for exactly this purpose. The secret lives in the gateway's request, never in the model's context.
  4. Cloudflare Access validates the service token at the edge (non-identity policy) and injects a signed JWT into the request to the Dodo worker.
  5. The Dodo worker validates the JWT itself (src/auth.ts, jose + JWKS) and maps service-token identities to the admin, so the browser can exercise the full UI and API.
  6. The session gets back structured results (title, DOM text, API statuses) plus a screenshot — closing the visual feedback loop.

Both secrets are chmod 600 files. The service token is scoped to a single Access app and can be revoked independently.

Why workers.dev was the problem

Cloudflare Access does not enforce at the edge on *.workers.dev hostnames — the Dodo UI shell was being served to anyone. The fix was a custom domain (dodo.jonnyparris.club) where Access enforces at the edge, plus disabling workers.dev entirely. The old public URL now returns 404.

How a Dodo session uses it

Add the gateway as an MCP integration in a Dodo session, then call browser_run with a step list:

dodo_add_mcp_config(name: "browser-run",
  url: "https://browser-run-worker.jonnyparris.workers.dev/",
  authToken: <AUTH_TOKEN>)

browser_run(steps: [
  { action: "setViewport", width: 1280, height: 800 },
  { action: "setHeaders", headers: {
      "CF-Access-Client-Id": "5b2704c262f1029b8af5da3485693fca.access",
      "CF-Access-Client-Secret": <SECRET> } },
  { action: "navigate", url: "https://dodo.jonnyparris.club/", waitUntil: "networkidle2" },
  { action: "screenshot" },
])
